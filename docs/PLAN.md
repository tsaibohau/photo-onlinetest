# 📑 OLT 線上測驗平台 — 專案計劃書（v0.1 草案，待放行）

> 一句話定位：**「拍一張考卷 → 變成互動測驗 → 交卷後一鍵生成 AI 解析提示詞」**
> 我們不做 AI，我們做「AI 的最佳入口」。使用者自己的 ChatGPT / Claude / Gemini 就是我們的解析引擎，零運算成本、無限擴展。

---

## 1. 產品目標與核心流程

```
 ┌─────────────┐   ┌──────────────┐   ┌─────────────┐   ┌────────────┐   ┌──────────────┐
 │ 上傳檔案/拍照 │ → │ 題目擷取與校對 │ → │ 產生 .olt 檔 │ → │ 開啟並作答   │ → │ 交卷 → 提示詞 │
 └─────────────┘   └──────────────┘   └─────────────┘   └────────────┘   └──────────────┘
   PDF/圖片/Word      AI 或手動辨識         可下載、可分享     專屬 UI / 計時      一鍵複製或直送 AI
   純文字/相機        出題者可編輯修正       離線也能用        自動計分（有答案時）
```

### 兩種角色
| 角色 | 做什麼 |
|---|---|
| **出題者**（老師、家長、自學者） | 上傳／拍照 → 校對題目 → 匯出 `.olt` |
| **作答者**（學生、自己） | 打開 `.olt` → 作答 → 交卷 → 拿提示詞去問 AI |

（同一個人可以兩種身分都是，例如：自己拍考古題給自己練。）

## 2. 題型支援（分階段解鎖）

| 題型 | 代號 | 作答 UI | 自動計分 | 階段 |
|---|---|---|---|---|
| 單選題 | `single` | Radio 選項 | ✅（有答案時） | MVP |
| 是非題 | `truefalse` | O / X 兩鈕 | ✅ | MVP |
| 多選題 | `multiple` | Checkbox，可設「全對才給分 / 部分給分」 | ✅ | MVP |
| 填空題 | `fill` | 文字輸入框（可多格） | ⚠️ 精確比對，模糊的交給 AI | Phase 2 |
| 簡答題 | `short` | 多行文字框 | ❌ 交給 AI 評分 | MVP |
| 題組（閱讀測驗） | `group` | 一段文章 + 多小題 | 依子題 | Phase 2 |
| 含圖題目 | 任何題型 + `image` | 題幹或選項附圖（從照片裁切） | — | Phase 2 |

> 沒有標準答案的考卷（只拍題目）也 OK：交卷時提示詞會請 AI「先解題、再對照作答者答案批改」。

## 3. 題目擷取：檔案／照片 → 結構化題目

這是整個產品最關鍵、也最燒錢的環節，因此設計成**三條路線**，由便宜到方便：

### 路線 A：手動 / 貼上文字（MVP，零成本）
- 支援直接貼上文字，內建解析器辨識常見格式：
  `1. 題目…  (A)… (B)… (C)… (D)…`、`答案：B` 等。
- 純文字 `.txt`、`.docx`（瀏覽器端用 mammoth.js 轉文字）、文字型 `.pdf`（pdf.js 取文字）都走這條。

### 路線 B：BYO-AI 轉檔（MVP，零成本，延續「讓使用者自己的 AI 做事」理念）
- 使用者上傳照片後，平台產生一段「**轉題目提示詞**」＋附上照片指引，
  使用者把照片和提示詞丟給自己的 AI，AI 回傳我們規定格式的 JSON，貼回來即完成匯入。
- 優點：完全不用後端金鑰、不用付費、隱私最佳。缺點：多一個複製貼上的步驟。

### 路線 C：一鍵 AI 辨識（Phase 3，需後端與 API 費用）
- Cloudflare Worker 代理呼叫視覺模型（Claude API 或 Cloudflare Workers AI 的視覺模型），
  照片上傳即自動回傳題目 JSON。
- 需處理：API 金鑰保管（Worker Secret）、流量限制（每 IP / 每日額度）、費用控管。
- 這是之後「付費方案 / 進階版」的天然切入點 💰。

**所有路線最後都會進入「校對編輯器」**：出題者可以逐題修改題幹、選項、正解、配分、題型，確認無誤才匯出。

## 4. `.olt` 檔案格式與「點開就能用」

### 4.1 檔案內容
`.olt` 本質是一個 **JSON 文件**（UTF-8），圖片以 base64 內嵌，單檔即可完整攜帶：

```jsonc
{
  "format": "olt",
  "version": 1,
  "meta": {
    "title": "國二數學 第三次段考",
    "subject": "數學",
    "createdAt": "2026-11-22T10:00:00Z",
    "timeLimitMin": 50,          // 可選
    "shuffle": false,            // 是否打亂題序
    "showAnswerAfterSubmit": true
  },
  "questions": [
    {
      "id": "q1",
      "type": "single",
      "stem": "下列何者為質數？",
      "options": ["4", "9", "11", "15"],
      "answer": [2],              // 可省略（無標準答案）
      "points": 5,
      "explanation": null,
      "image": null               // 或 "data:image/png;base64,..."
    },
    { "id": "q2", "type": "multiple", "stem": "...", "options": ["..."], "answer": [0, 3] },
    { "id": "q3", "type": "short", "stem": "請說明畢氏定理。", "reference": "參考答案（可選）" }
  ]
}
```

- 有 `version` 欄位，未來格式升級可向下相容。
- 有 JSON Schema 驗證，壞檔或被竄改會提示而不是當機。
- 選配：「隱藏答案」模式——正解以雜湊/簡易加密存放，避免學生直接用記事本打開看答案（註：純前端無法做到真正防作弊，這是「防君子」等級）。

### 4.2 「點開檔案就跑出專屬 UI」——誠實的技術說明 ⚠️
作業系統預設不認識 `.olt`，所以「雙擊就開」需要以下機制，**建議三管齊下**：

| 方式 | 體驗 | 支援度 |
|---|---|---|
| **① PWA 檔案關聯**（`manifest.json` 的 `file_handlers`）| 使用者「安裝」網站為 App 後，雙擊 `.olt` 直接用我們的 App 開啟 ✨ | Chrome / Edge 桌面版（Windows、macOS、ChromeOS）|
| **② 網站開啟 / 拖放** | 進網站 → 拖進 `.olt` 或點「開啟檔案」 | 所有瀏覽器、手機 |
| **③ 匯出「離線自帶 UI 版」** | 另存為 `xxx.olt.html`，內含完整 UI 與題目，任何裝置雙擊即用、不需網路 | 全平台（含 iPhone、LINE 傳檔）|

> iOS / Android 手機無法替自訂副檔名註冊開啟程式（Safari 不支援 file_handlers），
> 所以手機端主要靠 ② 與 ③。這點需要您確認是否接受（見第 10 節）。

## 5. 作答 UI 設計

- **風格**：乾淨、卡片式、大字體、適合手機單手作答；淺色/深色模式。
- **功能**：
  - 題目導覽列（已答 / 未答 / 標記待檢查 🚩）
  - 計時器（若設定時間限制，倒數結束自動交卷）
  - 作答進度自動暫存於 `localStorage`（不小心關掉不會白寫）
  - 交卷前確認「還有 N 題未作答」
- **交卷後**：
  - 成績摘要（有答案時）：分數、正確率、各題對錯
  - 錯題回顧
  - ⭐ **AI 提示詞面板**（下一節）

## 6. 交卷 → AI 解析提示詞（產品的靈魂）

### 6.1 提示詞內容結構
```
你是一位耐心的【{科目}】家教。以下是我剛完成的測驗「{標題}」作答紀錄，請幫我：
1. 逐題批改（沒有提供正解的題目請先自行解題）
2. 針對我答錯的題目，解釋正確觀念與我可能的迷思
3. 簡答題請依參考答案或專業標準給分並給出改進建議
4. 最後總結我的弱點，推薦 3 個加強方向與練習方法

【作答紀錄】
第1題（單選，5分）下列何者為質數？
  選項：(A)4 (B)9 (C)11 (D)15
  我的答案：(B)　正確答案：(C)　結果：❌
第3題（簡答）請說明畢氏定理。
  我的答案：……
  參考答案：……
...
【統計】總分 72/100，花費 38 分鐘
```

### 6.2 使用者操作
- 📋 **一鍵複製**提示詞
- 🚀 **直送按鈕**：「用 ChatGPT 開啟」「用 Claude 開啟」「用 Gemini 開啟」
  （支援網址帶入的平台直接帶入；不支援或過長時自動改成「已複製，請貼上」）
- 🎚️ 提示詞模式切換：**只問錯題** / **全部詳解** / **只要弱點分析**（控制長度與重點）
- 含圖題目：提示詞會註明「第 X 題附圖」，並提供圖片下載讓使用者一併上傳給 AI。
- 下載作答紀錄（`.json` / `.txt`）

## 7. 技術架構

| 層級 | 選擇 | 理由 |
|---|---|---|
| 前端框架 | **Vite + TypeScript + Preact**（React 相容、體積小）| 載入快、離線單檔 HTML 好打包 |
| 樣式 | 原生 CSS（CSS 變數做主題）| 不綁框架、檔案小 |
| 文件解析 | pdf.js、mammoth.js（瀏覽器端，按需載入）| 檔案不出使用者電腦，隱私佳 |
| 拍照 | `<input type="file" accept="image/*" capture>` + 前端壓縮／裁切 | 手機直接開相機 |
| 離線 / 安裝 | PWA（Service Worker + manifest `file_handlers`）| 支援 .olt 雙擊開啟 |
| 部署 | **Cloudflare Workers（Static Assets）/ Pages**，GitHub 連動自動部署 | 全球 CDN、免費額度大 |
| 後端（Phase 3）| Cloudflare Worker API：`/api/extract` 呼叫視覺模型 | Secret 管金鑰、可加限流 |
| 測試 | Vitest（解析器、提示詞產生器、格式驗證）+ Playwright（端到端作答流程）| 每次推送自動跑 |

### 目錄規劃
```
/
├─ src/
│  ├─ core/            # 與 UI 無關的純邏輯（可單元測試）
│  │  ├─ olt-schema.ts     # .olt 型別與驗證
│  │  ├─ text-parser.ts    # 純文字 → 題目
│  │  ├─ grader.ts         # 計分
│  │  └─ prompt-builder.ts # 交卷提示詞
│  ├─ pages/           # 首頁、建立測驗、校對編輯器、作答、結果
│  ├─ components/
│  └─ styles/
├─ public/manifest.webmanifest
├─ worker/             # Phase 3 才啟用的 API
├─ tests/
├─ docs/PLAN.md
└─ wrangler.toml
```

## 8. 部署與開發流程（GitHub → Cloudflare）

```
本地/雲端開發 ──push──▶ GitHub 分支 ──自動──▶ Cloudflare 預覽網址（每個分支一個）
                                   └─合併到 main─▶ Cloudflare 正式網址
```

1. 在 Cloudflare 後台連結 GitHub repo `photo-onlinetest`（需要您授權一次）。
2. Build 指令：`npm run build`，輸出目錄：`dist`。
3. 每個分支 push 都產生**預覽網址**，您可以先玩過再決定合併。
4. GitHub Actions 跑測試，紅燈不合併。

### 「確保每次都編輯最新檔案」的鐵律
- 每次動工前一律 `git fetch` + 合併遠端最新版本，再開始修改。
- 推送若被拒（遠端有新提交），先合併遠端、解衝突，**絕不強制覆蓋**。
- 需要拉到本地修改時：`git pull` → 改 → commit → push，Cloudflare 自動重新部署。
- 所有改動都走開發分支 `claude/online-quiz-platform-u4j0zw`，合併到 `main` 前由您確認。

## 10. 需要您拍板的決策 🖐️

1. **拍照辨識走哪條路？**
   - (建議) MVP 先做「路線 B：BYO-AI 轉檔」零成本，之後再加「路線 C 一鍵辨識」。

3. **答案保護**：是否需要「隱藏答案（防君子）」模式？
4. **網址 / 品牌名**：先用 Cloudflare 預設網域（`*.pages.dev` / `*.workers.dev`），之後再綁自訂網域？
5. **介面語言**：先只做繁體中文，還是一開始就預留中英切換？

## 11. 風險與對策

| 風險 | 對策 |
|---|---|
| 照片辨識不準（手寫、歪斜、模糊） | 一律經過「校對編輯器」；拍照時給拍攝提示；支援裁切 |
| 提示詞過長，網址帶入失敗 | 自動偵測長度改為複製貼上；提供「只問錯題」精簡模式 |
| 手機無法雙擊開啟 `.olt` | 提供 `.olt.html` 自帶 UI 版 + 網站拖放開啟 |
| 前端無法真正防作弊 | 明確定位為「練習/自學工具」，隱藏答案僅防君子 |
| 未來 API 費用失控 | Worker 限流、每日額度、可切換便宜模型 |
| 版本衝突 / 改到舊檔 | 第 8 節鐵律：先 fetch 再改、不強推、分支 + 預覽網址 |
